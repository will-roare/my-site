Core Concepts Explained Simply

To understand how GitHub works, it helps to understand its four foundational building blocks:

Repositories ("Repos"): The digital folders that hold your project's files, code, and entire history.

Commits: Code snapshots. Every time a developer saves their progress, they create a "commit" with a note explaining what changed.

Branches: Parallel workspaces. A developer can create a "branch" to test a new feature safely without breaking the main, working version of the app.

Pull Requests (PRs): Requests to merge code. When a feature is finished on a branch, the developer submits a PR asking teammates to review and approve the changes before they get added to the main code.
